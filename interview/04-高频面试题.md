# 04 · 高频面试题

> 每题四段式：**问题 → 追问链 → 怎么答 → 踩坑提示**。
> 压力题单独放最后一节 —— **那些不是最难的技术题，是最难答的诚实题。**

## A 组 · RAG 核心（答不出直接出局）

### A1 · 讲一下 RAG 的完整流程

**追问链**
```
Q1: RAG 完整流程是什么？
 └─ Q2: 每一步的输入输出分别是什么？
     └─ Q3: 你的流程里哪一步最容易出问题？
         └─ Q4: 出了问题你怎么发现、怎么定位？
```

**怎么答**
> 五步：查询改写 → 双路召回 → RRF 融合 → 内容去重 → 置信判控 → （达标）调 LLM 生成。
>
> - 输入是用户问题 + 最近 3 轮历史，输出是带引用的答案或拒答消息
> - 最容易出问题的是**置信判控** —— 它决定了这个系统是在「有依据地回答」还是「自信地编造」

**踩坑提示**
- ❌ 只讲「检索 → 生成」两步。面试官一听就知道你只是跑了个 demo，**没做过工程化**。
- ❌ 说「用 Rerank 模型做精排」。本项目**没有 Rerank**，被追问就塌了。

### A2 · 为什么用混合检索？向量路的增益是多少？

> ⚠️ **这是本项目最凶的一题，也是最能区分候选人的一题。**

**追问链**
```
Q1: 为什么 BM25 + 向量两路？
 └─ Q2: 那向量路到底带来多少收益？
     └─ Q3: 如果收益是 0，为什么不删掉？
         └─ Q4: 那这个项目跟纯 BM25 有什么区别？
```

**怎么答（诚实且有说服力的版本）**
> 混合检索的理由是**失败模式互补**：BM25 不可替代的是专名和数字（`GDP`、`5.2%`），向量不可替代的是跨表述检索（「高铁延长运行时间」vs「动车组新增班次」零字面重叠）。
>
> 但实测结论我必须说清楚：**向量路对召回率零增益**。BM25 单路、向量单路、融合三者的 TOP5 命中数完全相同，都是 49。融合排名与 BM25 不同 46/55 条（83.6%），说明它确实在重排，但对「答案是否进 TOP5」一次都没改变 —— 更好 0 / 更差 0 / 打平 46。
>
> 原因是 403 篇短新闻上 BM25 召回已经接近饱和，**不是向量没用，是这个规模的评估集区分不出差别**。

**踩坑提示**
- ❌ **「向量检索比关键词准」** —— 这是最常见的塌房点，因为真实数据是零增益。吹了之后面试官追问一层就穿了。
- ✅ 主动讲负面结论反而加分。**敢承认「我的评估集区分不出差别」，展示的是求真态度**，而这正是资深候选人的特征。

### A3 · RRF 为什么在你这个项目里失效了？

**追问链**
```
Q1: RRF 是什么？
 └─ Q2: 为什么不能直接用分数相加？
     └─ Q3: 你说它失效了，怎么失效的？
         └─ Q4: 那 k=60 你怎么定的？调过吗？
```

**怎么答**
> RRF 公式 `score(d) = Σ 1/(k + rank_i(d))`，只依赖排名不看分数，所以能融合 BM25（无上界）和余弦（[-1,1]）这种量纲完全不同的分数。
>
> 失效的地方不是**排序**，是**拿它当置信信号**。它只用排名、丢弃了分数幅度，在 403 篇小语料里几乎任何查询都能凑出双路命中，分数一律顶到上限 `2/(60+1)=0.0328`：
>
> | | min | 中位 | max |
> |---|---|---|---|
> | 正例 RRF 分 | 0.0313 | 0.0328 | 0.0328 |
> | 负例 RRF 分 | 0.0311 | 0.0325 | 0.0328 |
>
> 完全重叠，扫描全部 15 个阈值点，**找不到任何能同时拒答负例又作答正例的值**。
>
> 修法是把判据换成有余弦的向量相似度，RRF 继续做它擅长的排序。

**关于 k=60**：原论文的经验值，我没调过。诚实说。

**踩坑提示**
- ❌ 被问 k 怎么调时硬编「我扫了参数空间」。**说「没调，用的是原论文经验值」是安全且诚实的**。
- ✅ 这题真正在考：**你能不能发现一个已经上线的东西其实没生效**。

### A4 · 你的置信度是怎么算的？怎么证明它有效？

**追问链**
```
Q1: 三级判控是哪三级？
 └─ Q2: 阈值怎么定的？
     └─ Q3: 怎么证明有效？会不会只是恰好？
         └─ Q4: 会不会伤害正常问答？
```

**怎么答**
> 三级按可信度排序：向量余弦（主）→ BM25 分数（降级）→ RRF（兜底）。
>
> 数据支撑：向量余弦正例中位 **0.80** / 负例中位 **0.48**，有区分度；RRF 正负例完全重叠（见 A3）。阈值取 **0.55**。
>
> **有效性靠「零代价」来证明**：Recall@5 和 MRR@5 改前改后都是 93.9% / 90.5%，**一点没掉**，而负例误召回 100% → **16.7%**，拒答准确率 0% → **83.3%**。如果它换来了任何召回损失，就说明阈值切错了，是有代价的调参；现在这个结果是纯增益。
>
> 降级分支的必要性：向量 API 挂掉时 RRF 会退化成单路、恒定在 0.0082，统一阈值会把全部用例拒答掉。所以降级时改用有真实幅度的 BM25 分数。trace 里记 `gateMode` 以便事后区分「服务降级」和「质量下降」。

**踩坑提示**
- ❌ 说「阈值 0.55 是模型推荐值」。说「看了正负例的中位数分布，取在中间偏上，然后验证」。
- ⚠️ **这题容易顺手说出「原来是 100%」**。可以主动讲（展示改进过程），但**简历上绝对不写**。

### A5 · 怎么防幻觉？

**追问链**
```
Q1: 幻觉是什么，怎么防？
 └─ Q2: 你怎么知道你的答案没有幻觉？
     └─ Q3: 忠实度你测了吗？
```

**怎么答（两层 + 一个缺口）**
> 两层：
> 1. **答案带引用** `[1][2]`，用户能点回原文核对
> 2. **拒答前置** —— 置信度不达标在调 LLM 之前就返回，既省钱又根本性避免编造
>
> 但要说清楚：**我测的是检索层的质量（召回率、误召回率），没有测生成的忠实度** —— 也就是没验证答案里每句话是否真的来自检索到的原文。这是我目前最大的缺口，补法是人工抽样标注或 LLM-as-judge 做一致性核对。

**踩坑提示**
- ⚠️ **这是最容易被问穿的题**。说「引用机制保证了不幻觉」是错的 —— 引用只能让用户**能核对**，不能保证模型没胡说。
- ✅ 答法：讲清两层防护 → **主动承认没测忠实度** → 给出补法。三段缺一不可，承认缺口反而是加分项。

### A6 · 多轮对话怎么做的？

**追问链**
```
Q1: 多轮怎么实现的？
 └─ Q2: 历史存在哪？登录和未登录有区别吗？
     └─ Q3: 上下文怎么用的？直接拼到 prompt 里吗？
         └─ Q4: 为什么要改写查询？（这题是分水岭）
```

**怎么答**
> 登录用户历史存 MySQL `ai_chat` 表，未登录存 Redis（24 小时 TTL），靠请求头 `X-Anonymous-Id` 关联。上下文取最近 3 轮。
>
> ⚠️ **但关键在于：上下文只喂给生成层是不够的。** 多轮追问本身没有检索词 —— 用户说「那人均呢」，这句话直接拿去 BM25 和向量检索，**两边都是 0 分**，会直接触发拒答，用户看到的就是「这系统听不懂追问」。
>
> 所以检索层也必须改写：把**上一轮的问题**并进当前 query，变成「2023年GDP增速是多少 那人均呢」。
>
> 有个细节：**只带上一轮的问题，不带上一轮的回答**。回答里有 `[1][2]` 引用编号和整段叙述，拼进去会大量稀释本轮检索意图、把召回带偏 —— 这是实测发现的。

**踩坑提示**
- ❌ 「把历史拼进 prompt 就行」。这是**新手答案**，面试官会立刻追问「那检索呢」，你就得现编。
- ✅ **主动说「上下文要同时喂给检索层和生成层」**，这是做过多轮 RAG 的人才知道的点。

## B 组 · 工程化

### B1 · 索引为什么要版本化？

**追问链**
```
Q1: 离线索引怎么管版本？
 └─ Q2: 你校验了哪些东西？
     └─ Q3: 只校验模型名够吗？
         └─ Q4: 校验不通过会怎样？
```

**怎么答**
> 三重校验，缺一不可：语料指纹一致、embedding 模型名一致、矩阵行数与 ID 数一致。
>
> **只校验模型名是不够的** —— 同一个模型不同版本维度可能变，所以必须同时校验**向量维度**（1024）。行数校验是兜底，防止文件被部分覆盖导致映射错位。
>
> 任一项不满足就判定索引过期，**回退到运行时构建**而不是直接报错 —— 索引是加速项，不该让它成为可用性的单点。

**踩坑提示**
- ❌ 只说「校验模型名和维度」。追问会问「为什么还要校验行数」。

---

### B2 · 增量更新怎么做？中断了怎么办？

**追问链**
```
Q1: 语料更新了怎么重建索引？
 └─ Q2: 怎么知道哪些文档变了？
     └─ Q3: 中途挂了怎么办？
         └─ Q4: 全量重建要多久？成本多少？
```

**怎么答**
> 按**内容哈希**（title+description+content）比对，只有新 hash 才调 embedding。403 篇中新增 1 篇时，API 调用 403 → **1 次**，耗时 2793ms → **428ms**。
>
> 中断处理靠**进度文件断点续跑**，失败的文档单独记录下次重试，不从头再来。
>
> 全量重建是 403 次 embedding 调用（按批提交），成本按 token 计 —— 离线构建的成本是一次性的，摊到后续多次查询上很低。`python -m ai.ingest.cli cost` 可以查实际累计花费。

**追问预案**：
- 「为什么用内容哈希不用更新时间？」→ 更新时间会被误改污染，内容哈希是**内容本身**的标识，语义更准。**这是高频追问，要能立刻答出。**

### B3 · 性能怎么优化的？你怎么知道瓶颈在哪？

**追问链**
```
Q1: 检索有多慢？
 └─ Q2: 你怎么定位瓶颈的？
     └─ Q3: 优化前后分别是多少？
         └─ Q4: 缓存会不会有脏数据问题？
```

**怎么答**
> 先测量再优化。BM25 侧实测 403 篇下 tokenize 38.4ms + 建索引 35.9ms = **74.3ms**，而真正查询只要几毫秒 —— **90% 的时间花在准备索引上，不是花在检索**。语料不变时索引完全不变，所以按语料指纹缓存是安全的，优化后 **2.1ms**。
>
> 向量侧的瓶颈是 I/O 不是计算：逐条 GET 是 404 次 Redis 往返（1497ms），改批量读取降到 **1 次往返**，向量扫描 72.7ms → **0.26ms**。
>
> 核心思路是「**随语料缓存而非每次重算**」。

**踩坑提示**
- ⚠️ 性能数字会被追问「什么机器、什么并发」。如实说是**本地压测**，别暗示是高并发线上数据。

### B4 · SSE 流式接口你是怎么做计费的？

> 这题很细，但**能答出来说明你真的测过成本**。

**追问链**
```
Q1: 流式怎么实现的？
 └─ Q2: 怎么统计 token 消耗？
     └─ Q3: 流式和同步的计费口径一样吗？
```

**怎么答**
> SSE 是一串 `event: xxx\ndata: {...}\n\n` 的文本帧。计费上踩过一个坑：**usage 帧原本排在 finish_reason 帧之后**，导致流式调用**完全没被计费** —— 因为逻辑在终止帧就 return 了。修复后同步和流式都按真实 token usage 记账。

**踩坑提示**
- ❌ 编造「用了 tiktoken 估算」。如实答：优先用 API 返回的 usage，拿不到才估算。
- ✅ 这题是**细节诚实性**测试，能顺势展示「我会用监控发现漏计费」。

## C 组 · 后端基础

### C1 · 限流怎么做的？Redis 挂了怎么办？

**追问链**
```
Q1: 你说用了限流，怎么实现的？
 └─ Q2: 为什么用 Lua 不用 pipeline？
     └─ Q3: 令牌桶怎么实现的？
         └─ Q4: Redis 挂了会怎样？ ← 这题决定你够不够 senior
```

**怎么答**
> 令牌桶，Redis 里存 `{当前令牌数, 上次更新时间}`，Lua 脚本保证「读 → 判断 → 扣减 → 写回」的**原子性** —— 用 pipeline 分多条命令的话，中间可能被别的请求插入，导致超发。
>
> Redis 故障时 **fail-open 直接放行**，同时打 warning 日志。理由是：限流是**保护措施**，为了它牺牲可用性是本末倒置 —— 数据库已经扛不住的时候，再拒掉正常请求只会让故障更严重。

**踩坑提示**
- ❌ 说「Redis 挂了降级成本地限流」。那是在造需求，本地单实例的计数毫无意义。
- ✅ **fail-open 的理由要讲出来**，这题就在考你的取舍判断。

### C2 · 唯一约束和先查后写，哪个好？

**追问链**
```
Q1: 怎么保证不插入重复数据？
 └─ Q2: 先查后写有什么问题？
     └─ Q3: 并发下会发生什么？
```

**怎么答**
> **先查后写在并发下不安全** —— 两个请求可能同时查到「不存在」，然后都执行插入。必须依赖数据库的**唯一约束**兜底，让数据库做最终裁决。
>
> 这个项目里我就踩了：原本 `content_hash` 是一对一唯一约束，后来的重复数据**静默覆盖**了先前记录 —— 表面没报错，实际丢了数据。改成**一对多映射**（同一 hash 允许多条记录）才真正修好。

**踩坑提示**
- ❌ 说「我用了 Redis 分布式锁」。**能用数据库唯一约束解决的就别上分布式锁** —— 多一个依赖多一个故障点。答这个会显得过度设计。

### C3 · 相关推荐怎么做的？

**追问链**
```
Q1: 推荐怎么实现的？
 └─ Q2: 冷启动怎么办？新内容没有点击数据。
     └─ Q3: 怎么保证强相关？
```

**怎么答**
> **人工关联优先 + 实时同分类热门兜底**。
>
> 强相关靠人工配置，保证「读完 A 推荐 B」一定说得通；没有人工配置的冷启动内容，退回同分类按热度排序，保证列表不空。
>
> 增删关联时主动失效缓存。演示脚本会按规则批量灌入一批人工关联。

**追问预案**：
- 「为什么不做协同过滤？」→ 403 篇语料撑不起协同过滤的矩阵，而且**冷启动问题无解**。诚实说明比硬编算法强。

## D 组 · 压力题（最难的不是技术，是诚实）

> 这些题**一定会被问到**。提前准备，比被问到现想强。

### D1 · 403 篇是不是根本没法落地？

**面试官为什么问**
> 他想知道你**有没有考虑过规模**。如果完全没想过，说明你只做了个玩具。

**怎么答（正面承认 + 给出判断依据）**
> 是规模限制，我不回避。但要分清两件事：
>
> **检索方式没选错**：403 篇全量扫描用 NumPy 矩阵乘只要 0.26ms，引入 FAISS/Milvus 是**净增运维成本、零收益**。真正需要 ANN（HNSW/IVF）通常在百万级。
>
> **扩到大规模时怎么改**：向量层是独立封装的（`VectorMatrix.search()`），换成 FAISS/Milvus 只需要改这个方法的内部实现，**调用方一行都不用改**。BM25 那边同理，换成 Elasticsearch。
>
> 我的取舍是：**先把检索逻辑做对，规模化是换实现而不是重写**。实际上线会先扩语料到十万级并替换索引层，检索策略不变。

**踩坑提示**
- ❌ 硬撑「403 篇完全够用」。**没说服力** —— 面试官清楚真实系统不会有这个量级。
- ❌ 说「以后数据多了就上向量数据库」然后说不出**具体怎么换**。要能说出「改哪个类、调用方不受影响」。

### D2 · 你为什么不用 LangChain / LangGraph？

**追问链**
```
Q1: 为什么不加 LangChain？
 └─ Q2: 不用框架的代价是什么？
     └─ Q3: 什么情况下你会用框架？
```

**怎么答**
> LangChain 主要的价值是**生态和集成**：多数据源连接器、丰富的 Loader/Splitter、LangSmith 观测。我这个场景**数据源单一**（MySQL 里的新闻）、**检索策略明确**（BM25+向量+RRF），框架的通用抽象反而挡在中间。
>
> **不用框架的代价我说得清**：工具链要自己搭（我手写了 trace 和评估 runner）、生态插件用不上、将来换模型要自己适配。
>
> **但我不是说框架不好** —— 如果要做 Agent 编排、多轮工具调用、需要快速接入多种数据源，我会用 LangChain。这个项目没有 Agent，引入它属于杀鸡用牛刀。

**踩坑提示**
- ❌ 贬低框架（「LangChain 垃圾、自己写更好」）。**面试官会觉得你狂妄或不懂行业**。
- ✅ 正确姿势：**讲清楚取舍，而不是站队**。手写和自己造轮子是两回事 —— 你的 RRF 融合和置信判控是业务特有的，不是重复造轮子。

### D3 · 这个项目就是纯做项目练手吧？

**面试官为什么问**
> 这是**动机质疑**。你如果说是练手，前面所有技术细节的分量都会打折。

**怎么答**
> 起因是我自己用新闻 APP 时的真实痛点：想找一条看过的报道，记不清标题只记得大概内容（「去年 AI 出政策那次」），而搜索只能匹配标题，一条都搜不到。
>
> 核心判断是我**把痛点量化成了可测指标**才开工的：不是「做个语义搜索」这种模糊目标，而是「正例 Recall@5 要多少、负例误召回要压到多少」。整个项目的决策（融合策略、置信阈值、要不要向量库）都是拿这些指标推出来的。

**踩坑提示**
- ❌ 说「因为现在 AI 很火，想学」。**这题直接判死刑。**
- ❌ 硬吹「已经上线，有用户」。**一问就穿。**
- ✅ 讲**真实痛点 + 量化目标**，不要编造商业故事。

### D4 · 向量召回增益是 0，为什么不删掉？

**怎么答**
> 三个原因：
>
> 1. **零增益是这个规模的现象，不是向量本身的性质。** 评估集在 403 篇上区分不出差别，换到上万篇语料、多样性更强的场景，跨表述检索的价值才会显现。
> 2. **它确实在改变排序**（46/55 条排名不同），说明不是完全没起作用，是没影响到召回这个指标。
> 3. **删它的收益是零。** 它没有造成损失（Recall/MRR 都没掉），而删掉意味着放弃了跨表述检索的能力。
>
> 真正该做的是**扩展评估集规模**来验证它到底有没有用 —— 我把 `SINGLE_PATH_WEIGHT` 标记为「未经有效验证」就是这个意思。

**踩坑提示**
- ❌ 「因为向量是未来趋势」—— 趋势不能替代验证。
- ✅ **区分「没证明有用」和「已证明无用」**：前者要补验证，后者才该删。这题考的是实验态度。

### D5 · 你为什么用 `SINGLE_PATH_WEIGHT`？它有效果吗？

> ⚠️ **这题有个陷阱：参数存在，但实测无效。**

**怎么答**
> 我原本设这个参数是为了区分「只被一路召回」和「两路都召回」的文档 —— 想法是单路命中的证据强度天然更弱，该降权。
>
> 但实测**完全无效**：取 1.0 / 0.8 / 0.5 / 0.3 / 0.0 五档，召回合计和 MRR 合计**全部相同**（49 / 44.33）。
>
> 更重要的是我因此发现了一个**方法论错误**：早期我用「假向量」测出「融合后 MRR 从 90.5% 腰斩到 50.7%」，并据此认为「融合在单路退化时缺乏保护」—— **这个结论是假向量的伪影，真向量下融合是打平的，该结论已作废**。
>
> 所以这个参数我保留了（默认 0.5 不动），但标记为**未经有效验证**，等评估集扩大后重新验。

**踩坑提示**
- ❌ 不知道这个参数无效，照着设计意图讲。**面试官只要问一句「有效果吗」就穿了。**
- ✅ 这题的价值全在**后半段**：承认方法论错误、并说明怎么发现的。这是**全场最能加分的一题**，因为它展示的是「用数据推翻自己」的能力。

### D6 · 你这个项目有什么没做好的？

> **这题几乎必问，考的是自我认知。**

**怎么答（挑真实缺口，且都带补法）**
> 三个明确的缺口：
>
> 1. **没测生成的忠实度** —— 我只验证了检索层（召回、拒答），没验证答案内容是否真的来自证据。补法是人工抽样或 LLM-as-judge 做一致性核对。
> 2. **评估集只有 55 条** —— 作为回归门禁有价值，但统计意义上样本量不足，它证明不了效果多好。
> 3. **没做真实流量下的冷启动和压力验证** —— 热榜的排序公式是在可控数据上设计的，没有真实点击分布检验过。

**踩坑提示**
- ❌ 说「没什么问题」。**面试官不信，等于暴露你没有审视过自己的项目。**
- ❌ 罗列一堆无关痛痒的缺点（UI 不够好看）。**要挑技术/业务核心的缺口，且每个都要能接上「我知道怎么补」**。
- ⚠️ **但这些不要写进简历** —— 见 `01-简历写法.md` 规则 2。写进简历是减分，被问到才是加分。

## 🎯 最后的三条心法

1. **答不出来就说不知道，但要接上「我怎么去弄明白」。** 面试官不怕你不知道，怕你不懂装懂。

2. **敢讲负面结论。** 「我的向量路零增益」「我的参数验证无效」「我的方法论错过一次」—— 这些话在面试里是**可信度的来源**，不是减分项。

3. **每个答案都要有数字。** 没有数字的答案是形容词。
