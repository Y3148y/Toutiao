# 02 · 项目介绍

> 面试时**照着讲**。本文分四部分：背景 → 功能 → 架构 → 演示脚本。

---

## 🎤 背景（30 秒，最高频开场题）

被问「介绍一下你这个项目 / 讲讲背景」，**直接答这三句，不要铺垫**：

> **我做的是一个新闻资讯平台的后端 —— 用户看新闻，不发新闻。**
>
> **起因是我自己用新闻 APP 时的一个具体痛点：想找一条以前看过的报道，记不清标题，只记得大概内容**，比如「去年 AI 出政策那次」。但搜索只能匹配标题，这种表述一条都搜不到。
>
> **所以我给已有内容加了语义检索和问答入口：用户用自然语言问，系统从已有新闻里找出相关的几条，并明确标出答案出自哪几篇。**

### ❌ 三个必须避开的开场错误

| 错误说法 | 为什么踩雷 |
|---|---|
| 「RAG 是现在最火的 AI 方向，所以我想学习一下…」 | 动机是「跟风」，面试官立刻判定为练手项目 |
| 「我做了一个资讯平台，包含用户模块、新闻模块、收藏模块…」 | 罗列模块名，面试官没时间理你，且没说你解决了什么问题 |
| 「我做了一个 AI 问答系统，基于 LangChain + Milvus…」 | 技术堆砌先于问题定义，且本项目**没用**这些（被问到见 `04` 压力题） |

**核心原则：先说「什么应用」，再说「为什么做」，最后说「有什么功能」。** 面试官问「背景」，要的是这三样，不是架构图。

## 📦 功能（说清楚边界，别夸大）

这是一个**消费端**资讯平台 —— 内容和用户行为：

| 模块 | 功能 |
|---|---|
| **内容消费** | 首页信息流、分类列表、新闻详情、热度榜 |
| **搜索** | 关键词搜索 + **语义问答**（自然语言提问，答案带引用溯源） |
| **发现** | 相关推荐（读完一篇推荐同主题的几篇） |
| **用户** | 注册、登录、Token 鉴权、修改资料/密码、收藏、阅读历史 |

**边界（被问到再说，简历不写）**：
- **没有用户发布内容**（UGC）—— 这是纯消费平台，不做社区
- **没有做消息通知**
- 前端是独立项目，后端只提供 API

### AI 能力具体是什么

一句话：**基于新闻语料的问答，但答案必须可溯源，证据不足就拒答。**

- 用户提问 → 检索相关新闻 → 有把握才调模型生成，答案标注引用哪几篇
- **证据不足时直接拒答**，而不是让模型自由发挥
- 支持**多轮追问**（「那人均呢」能继承上一轮的 GDP 主题）
- 问答历史落库（登录用户）或存 Redis（匿名用户，24 小时过期）

## 🏗️ 架构（被追问「整体架构」时才展开）

```
                     ┌─────────────────────────────┐
   HTTP 请求  ──────▶  FastAPI 路由层 (27 API)      │
                     │  · 统一 code/message/data   │
                     │  · Token 鉴权 (需登录接口)   │
                     │  · Redis 令牌桶限流          │
                     └──────────┬──────────────────┘
                                │
             ┌──────────────────┼──────────────────┐
             ▼                  ▼                  ▼
      ┌────────────┐   ┌──────────────────┐  ┌──────────────┐
      │  业务 CRUD  │   │   混合检索链路    │  │  用户/收藏    │
      │ feed/search │   │  ① 查询改写(多轮) │  │  history     │
      │ hot/related│   │  ② BM25 + 向量   │  │  favorite    │
      └─────┬──────┘   │  ③ RRF 融合      │  └──────┬───────┘
            │          │  ④ 内容哈希去重    │         │
            │          │  ⑤ 三级置信判控    │         │
            │          └────────┬─────────┘         │
            │                   │                   │
            │            ┌──────┴──────┐            │
            │            │  达标→生成   │            │
            │            │  不达标→拒答 │            │
            │            └──────┬──────┘            │
            ▼                   ▼                   ▼
    ┌───────────────────────────────────────────────────┐
    │  MySQL (异步 SQLAlchemy)   │   Redis (缓存/限流)   │
    │  403 篇新闻 · 27 个 API     │   DashScope LLM API   │
    └───────────────────────────────────────────────────┘
```

### 检索链路的六步（最高频技术追问，务必背熟）

```
用户提问
  ↓ ① 查询改写：把上一轮问题并入当前 query（「那人均呢」→「2023 GDP 那人均呢」）
  ↓ ② 双路召回：BM25 20 条 + 向量 20 条
  ↓ ③ RRF 融合：score = Σ 1/(60+rank)，只按排名不算分数
  ↓ ④ 内容哈希去重：重复新闻只留融合分最高的一条
  ↓ ⑤ 三级置信判控：向量余弦 → BM25 分数 → RRF 兜底
  ↓
  ├─ 达标 → 调 LLM 生成，答案带 [1][2] 引用
  └─ 不达标 → 直接拒答，提示换个问法（不调 LLM，省钱且防编造）
```

## 🎬 3 分钟演示脚本

**面试时如果有环境，主动演示是巨大的加分项。** 按顺序跑，每步都有明确预期输出。

### 准备（会前 10 分钟）

```bash
# 1. 启动基础设施 + 应用
docker compose up -d

# 2. 灌入演示数据（幂等，可重复执行）
python -m scripts.seed_demo
#    创建演示账号 demo / demo123456，并批量写入人工相关推荐（条数随语料而定）

# 3. 确认路由全部注册成功（27 个业务/AI 接口 + 1 个根路径 = 28）
python -m scripts.check_routes
#    输出：OK: 28 paths
```

> 如果用的是别人的 fork，**记得先改掉演示账号密码**，或者干脆不用它。

### 演示 5 步

**第 1 步 · 常规业务：首页信息流**
```bash
# feed 支持三种排序：latest(默认) / hot / personalized
curl "http://localhost:3001/api/news/feed?page=1&pageSize=5&sort=latest"
```
✅ **看点**：正常返回分页新闻。这是基础业务，证明不是只做了 AI。

**第 2 步 · 关键词搜索（BM25 能力）**
```bash
# keyword 必填，可选 categoryId / page / pageSize
curl "http://localhost:3001/api/news/search?keyword=GDP&pageSize=5"
```
✅ **看点**：能搜到专名「GDP」相关报道 —— 这正是纯向量检索最容易漏掉的一类查询。

**第 3 步 · 语义问答 —— 这是核心，必须演示**
```bash
curl -X POST "http://localhost:3001/api/ai/news-qa/sync" \
  -H "Content-Type: application/json" \
  -d '{"question":"2023年GDP增速是多少"}'
```
✅ **看点**：返回基于新闻语料的回答，**答案里带 `[1][2]` 引用编号**。

**第 4 步 · 多轮追问（证明不是单轮摆设）**

多轮靠**会话标识**串起来，**不需要在请求体里传 session_id**：

| 场景 | 怎么带上下文 | 历史存哪 |
|---|---|---|
| 已登录 | 请求头 `Authorization: Bearer <登录返回的 token>` | MySQL `ai_chat` 表（持久） |
| 未登录 | 请求头 `X-Anonymous-Id: <上次响应头返回的值>` | Redis（24 小时 TTL） |

匿名用户首次提问时，服务端会生成 ID 并**通过响应头 `X-Anonymous-Id` 返回**，前端存下来下次带上即可。

```bash
# ① 先问一轮，从响应头里拿到 X-Anonymous-Id
curl -i -X POST "http://localhost:3001/api/ai/news-qa/sync" \
  -H "Content-Type: application/json" \
  -d '{"question":"2023年GDP增速是多少"}'
# 响应头里找：X-Anonymous-Id: 3f9a...   ← 复制出来

# ② 带上这个 ID 再问一次「那人均呢」
curl -X POST "http://localhost:3001/api/ai/news-qa/sync" \
  -H "Content-Type: application/json" \
  -H "X-Anonymous-Id: 3f9a..." \
  -d '{"question":"那人均呢"}'
```
✅ **看点**：第 ② 问的「那人均呢」本身没有任何检索词，系统通过**查询改写**把它补成「2023年GDP增速是多少 那人均呢」，因而能继承上一轮主题继续作答。

> ⚠️ **这步一定要会前彩排。** 如果第 ② 问答不出来，多半是第 ① 步的 ID 没复制对。

**第 5 步 · 拒答（最能体现产品思维的一步）**
```bash
curl -X POST "http://localhost:3001/api/ai/news-qa/sync" \
  -H "Content-Type: application/json" \
  -d '{"question":"明天上海天气怎么样"}'
```
✅ **看点**：系统**明确拒答并说明理由**，而不是硬编一个答案。

> 拒答的判定发生在**调 LLM 之前** —— 置信度不达标就直接返回，省一次模型调用的钱。
> 如果你想从 trace 里确认它走的是哪一级判据，打开 `AI_TRACE_ENABLED=true` 后查 Redis `ai:trace:*`。

> **第 5 步是本项目的灵魂。** 很多候选人的 RAG 只会演示「答得对」，
> 演示「答不了」才能证明你理解了 RAG 的真正难点是**控制什么时候不该答**。

## 📌 被问「你在这个项目里做了什么」时的答法

> 「这是我从 0 到 1 独立做的个人项目 —— 后端架构、检索链路、离线索引、评估体系都是我自己设计的。
> 前端是另一边的同学/我自己另外开的项目做的，后端这边 27 个 API 都是我实现的。」

**要点**：
- 明确说「独立完成」，不要模糊
- 如果有合作的部分（如前端），**主动划清边界**，不要含糊其辞 —— 面试官会追问
- 强调「设计」而不是「写」，前者体现思考深度
