## ⚠️ 使用前必读：三条铁律

这份材料里有些话是专门写给**面试现场**的，和写代码的直觉相反，请务必看完再投简历。

1. **不主动暴露短板。** 项目有边界（403 篇语料、没测忠实度），这些**被问到再答**，答得诚实且有判断力反而加分；主动写在简历上，面试官只会记住缺陷。

2. **不写中间态数值。** 「准确率从 100% 降到 16.7%」这种写法像代码写坏了。简历只写**最终结果**（「负例误召回率 16.7%」），中间的踩坑留给面试问答讲。

3. **自我介绍不展开项目细节。** 简历上有的东西面试官自己会看。自我介绍只讲「个人信息 + 技能 + 实习产出 + 项目一句话」，细节等他追问。

这三条的完整解释和改写示例见 [`01-简历写法.md`](01-简历写法.md)。

## 📊 本项目的事实清单（可直接引用）

这些数字全部来自代码与实测，是面试时**可以放心说**的部分：

| 项目 | 值 |
|---|---|
| 业务性质 | 消费端新闻资讯（用户读，不发布） |
| 框架 | FastAPI + SQLAlchemy 2.0（异步）+ MySQL + Redis |
| API 数量 | 27 个（22 业务 + 5 AI） |
| 测试数量 | 295 个，全绿 |
| 语料规模 | 403 篇新闻 |
| 评测集 | 55 条（正例 49 + 负例 6） |
| Embedding | `qwen3.7-text-embedding`，1024 维 |
| 生成模型 | `deepseek-v4-flash-0731` |
| 检索方式 | BM25 + 向量双路，RRF（k=60）融合 |
| 召回质量 | Recall@5 **93.9%** / MRR@5 **90.5%** / nDCG@5 **91.4%** |
| 置信门控 | 三级判据（向量余弦 → BM25 → RRF 兜底） |
| 拒答能力 | 负例误召回率 **16.7%**，拒答准确率 **83.3%** |

> ⚠️ 数字以 [`ai/eval/README.md`](../ai/eval/README.md) 为准。如果你要更新简历，先跑一遍评估再改。
